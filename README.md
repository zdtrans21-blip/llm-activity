# 🤖 LLM: Анализ документов — активити для бизнес-процессов Битрикс24

Приложение регистрирует кастомное активити в дизайнере бизнес-процессов Битрикс24.
Активити скачивает документы (PDF, DOCX, TXT, PNG, JPG), извлекает из них текст и отправляет его в выбранную LLM с вашим системным промтом.

---

## Требования

- Node.js 18+
- Аккаунт на VibeCode (vibecode.bitrix24.tech)
- Портал Битрикс24 (коммерческий тарифный план для bizproc.activity.add)

---

```
llm-activity/

```

## Установка и запуск

### 1. Клонируйте проект и установите зависимости

```bash
cd llm-activity
npm install
```

### 2. Настройте переменные окружения

```bash
cp .env.example .env
```

Отредактируйте `.env`:

```env
VIBE_API_KEY=vibe_app_local_ваш_ключ
BITRIX_DOMAIN=ваш-домен.bitrix24.ru
PORT=3000
APP_URL=https://ваш-публичный-url
```

### 3. Задеплойте на VibeCode (Galaxy App)

```bash
# Архивируйте проект (без node_modules)
tar -czf app.tar.gz --exclude=node_modules --exclude=.env .

# Задеплойте через VibeCode API
node -e "
const fs = require('fs');
const axios = require('axios');
const archive = fs.readFileSync('app.tar.gz').toString('base64');
axios.post('https://vibecode.bitrix24.tech/v1/infra/servers', {
  name: 'llm-activity',
  source: { content: archive },
  runtime: 'node20',
  start: 'node index.js',
  install: 'npm install',
  env: {
    VIBE_API_KEY: process.env.VIBE_API_KEY,
    BITRIX_DOMAIN: process.env.BITRIX_DOMAIN,
    PORT: '3000'
  }
}, { headers: { 'X-Api-Key': process.env.VIBE_API_KEY } }).then(r => console.log(r.data)).catch(e => console.error(e.response?.data || e.message));
"
```

Или используйте скрипт `deploy.js` (см. ниже).

### 4. Получите публичный URL

После деплоя получите URL вашего Galaxy-приложения:

```bash
curl -H "X-Api-Key: ВАШ_КЛЮЧ" https://vibecode.bitrix24.tech/v1/infra/servers
```

Запишите URL вида `https://xxx.vibecode.app` в переменную `APP_URL`.

### 5. Зарегистрируйте активити в Битрикс24

```bash
APP_URL=https://xxx.vibecode.app node install.js
```

Или откройте в браузере: `https://xxx.vibecode.app/install`

### 6. Проверьте в дизайнере бизнес-процессов

Откройте Битрикс24 → Бизнес-процессы → Конструктор → раздел **"Действия приложений"** — там должно появиться "🤖 LLM: анализ документов".

## Настройка активити в дизайнере БП

| Поле | Описание | Пример |
|------|----------|--------|
| **LLM провайдер** | openai / anthropic / openrouter / ollama / custom | `openai` |
| **API URL** | Endpoint LLM | `https://api.openai.com/v1/chat/completions` |
| **Название модели** | ID модели | `gpt-4o` |
| **Логин (Basic Auth)** | Опционально, только для Basic Auth | *(пусто)* |
| **API-ключ** | Секретный ключ LLM | `sk-...` |
| **Ссылки на документы** | ID файлов Disk или прямые URL | `disk://123` |
| **Системный промт** | Задание для LLM | *см. примеры ниже* |
| **Куда выводить** | `comment` или `variable` | `comment` |
| **Имя переменной** | Если `output_mode=variable` | `llm_analysis` |

### Выходные переменные (RETURN_PROPERTIES)

- `llm_result` — полный текст ответа LLM
- `llm_status` — `success` или `error`
- `llm_error_message` — текст ошибки (если `llm_status=error`)

## Примеры системных промтов

### Сравнение двух договоров

```
Сравни два предоставленных договора. Найди и перечисли все расхождения в:
1. Условиях оплаты (сроки, суммы, штрафы)
2. Сроках исполнения обязательств
3. Ответственности сторон
4. Форс-мажорных обстоятельствах
5. Порядке расторжения договора

Оформи в виде таблицы: | Пункт | Договор 1 | Договор 2 | Комментарий |
```

### Проверка акта на соответствие счёту

```
Проверь соответствие акта выполненных работ счёту-фактуре. 
Убедись, что:
1. Суммы совпадают (с учётом НДС)
2. Наименования услуг/товаров идентичны
3. Количество и единицы измерения совпадают
4. Реквизиты сторон соответствуют

Если есть расхождения — перечисли их. Если всё верно — напиши "Документы соответствуют друг другу".
```

### Поиск орфографических и грамматических ошибок

```
Проверь текст документа на:
1. Орфографические ошибки
2. Грамматические ошибки  
3. Пунктуационные ошибки
4. Стилистические несоответствия для делового документа

Для каждой ошибки укажи: строку/абзац, оригинальный текст, исправленный вариант.
Если ошибок нет — напиши "Документ не содержит ошибок".
```

### Извлечение ключевых данных из контракта

```
Извлеки из контракта следующие данные и верни в формате JSON:
{
  "номер_договора": "...",
  "дата_заключения": "ДД.ММ.ГГГГ",
  "сторона_1": { "название": "...", "инн": "...", "адрес": "..." },
  "сторона_2": { "название": "...", "инн": "...", "адрес": "..." },
  "предмет_договора": "...",
  "сумма": "...",
  "срок_действия": "...",
  "условия_оплаты": "..."
}
```

## Поддерживаемые LLM-провайдеры

| Провайдер | URL | Формат авторизации |
|-----------|-----|-------------------|
| **OpenAI** | `https://api.openai.com/v1/chat/completions` | Bearer ключ |
| **Anthropic** | `https://api.anthropic.com/v1/messages` | x-api-key |
| **OpenRouter** | `https://openrouter.ai/api/v1/chat/completions` | Bearer ключ |
| **Ollama (локальный)** | `http://localhost:11434/v1/chat/completions` | Без ключа (оставьте `-`) |
| **Custom** | Ваш URL | Bearer или Basic Auth |

## Важные замечания

### Таймаут бизнес-процесса

> ⚠️ **Установите таймаут ожидания ответа от активити не менее 10 минут** в настройках бизнес-процесса.
> 
> LLM может обрабатывать большие документы долго (1–5 минут). Если таймаут БП меньше, процесс прервётся до получения ответа.
> 
> Настройка: Конструктор БП → свойства ноды "LLM: анализ документов" → **Таймаут ожидания** → 600 секунд.

### Безопасность API-ключей

- API-ключи LLM **не хранятся** на сервере — они передаются напрямую в параметрах активити каждый раз при запуске.
- Используйте зашифрованные поля Битрикс24 для хранения ключей в переменных БП.

### Ограничения

- Максимальный размер одного документа: 100 MB
- Таймаут запроса к LLM: 120 секунд
- Формат .doc (старый Word) не поддерживается — конвертируйте в .docx или PDF

Смотрите логи сервера в VibeCode:
```bash
curl -H "X-Api-Key: ВАШ_КЛЮЧ" "https://vibecode.bitrix24.tech/v1/infra/servers/ВАШ_SERVER_ID/logs?limit=100"
```

Каждый запрос от Битрикс24 логирует:

- `document_id`  
- Значения `properties`
- Ход обработки каждого шага
